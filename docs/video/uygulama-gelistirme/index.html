Uygulama Geliştirme

Dört adımda yeni bir uygulama, uyulması gereken kurallar ve iki çözünürlükte çalışan ölçü sabitleri kalıbı.

Bir uygulama nasıl yaşar
1 / 10
Ekranın sahibi her an yalnızca bir uygulamadır. Geçişleri app_manager animasyonla yapar.
Yeni bir uygulama eklemek dört adımdır: dosyaları oluşturmak, kimlik vermek, kaydetmek ve isterseniz ana menüye bir kutucuk eklemek.
Adım 1: Uygulama dosyaları (başlık)
2 / 10
// src/apps/myapp/myapp_app.h
#pragma once
#include "../../core/app_manager.h"
const app_interface_t* myapp_get_interface(void);
Her uygulama iki dosyadan oluşur ve dışarıya yalnızca bir fonksiyon verir: kendi get_interface fonksiyonu.
Yerleşik uygulamaların tamamı bu kalıpla yazılmıştır.
Adım 1: Uygulama dosyaları (kaynak)
3 / 10
// src/apps/myapp/myapp_app.cpp
#include "myapp_app.h"

static void my_on_start(lv_obj_t* screen) {
  lv_obj_t* lbl = lv_label_create(screen);
  lv_label_set_text(lbl, "Merhaba NarRTOS");
  lv_obj_center(lbl);
  app_manager_enable_gestures(screen); // swipe'lar ekrana ulaşsın
}
static void my_on_stop(void) { /* on_start'ta ayrılanları bırak */ }
static bool my_on_event(const os_event_t* e) {
  // örn. EVENT_TIME_UPDATED geldiğinde etiketi tazele
  return false;                        // true = olayı tükettim
}
on_start içinde arayüz yalnızca verilen ekrana kurulur. app_manager_enable_gestures çağrısı, kaydırma jestlerinin bu ekrana ulaşmasını sağlar.
on_stop, on_start içinde ayrılan her kaynağı serbest bırakır. on_event ise ilgilenmediği olaylarda false döner.
Adım 1: Arayüz tablosu
4 / 10
static const app_interface_t my_app = {
  .on_start  = my_on_start,
  .on_resume = NULL, .on_pause = NULL,
  .on_stop   = my_on_stop,
  .on_event  = my_on_event,
  .name      = "myapp",
};
const app_interface_t* myapp_get_interface(void) { return &my_app; }
Kullanılmayan yaşam döngüsü fonksiyonları NULL bırakılabilir. name alanı yalnızca log kayıtlarında kullanılır.
Adım 2 ve 3: Kimlik ve kayıt

// core/os_config.h
typedef enum {
  APP_ID_WATCHFACE = 0,
  ...
  APP_ID_STORE     = 11,
  APP_ID_MYAPP     = 12,   // <-- YENİ: her zaman APP_ID_COUNT'tan önce
  APP_ID_COUNT
} app_id_t;

// core/app_manager.cpp
#include "../apps/myapp/myapp_app.h"
void app_manager_init(void) {
  ...
  app_manager_register(APP_ID_MYAPP, myapp_get_interface()); // <-- YENİ
}
Yeni APP_ID sabiti her zaman APP_ID_COUNT satırının önüne eklenir.
Bütün uygulamalar tek bir yerde, app_manager_init fonksiyonunda kaydedilir. main.cpp dosyasına dokunulmaz.
Adım 4: Derle ve çalıştır

pio run -e esp32s3_wearable -t clean
pio run -e esp32s3_wearable -t upload   # cihazda: Launcher'da yeni kutucuk

Kayıt, uygulamayı çalıştırılabilir yapar. Menüde görünmesi için ana menü ızgarasına bir kutucuk eklenir.
Kodda her değişiklikten sonra önce clean ile temizleyin, ardından derleyip yükleyin.
Uyulması gereken kurallar
7 / 10
  • Arayüz yalnızca on_start fonksiyonuna verilen ekrana kurulur. Ekran nesnesi saklanıp başka ekranlara dokunulmaz.
  • Başka bir görevden yapılan arayüz güncellemeleri ui_service_lock ve unlock çağrıları arasına alınır.
  • on_stop, on_start içinde ayrılan her kaynağı (zamanlayıcı, tampon, servis aboneliği) bırakır; çünkü uygulamalar tekrar tekrar açılıp kapanır.
  • Servisleri sürekli yoklamayın; olayları dinleyin.
Bu dört kural, çok uygulamalı bir sistemde kaynak sızıntısını ve çakışmaları önler.
Gerçek örnek: WatchFace on_event
8 / 10
static bool on_event(const os_event_t* event)
{
  if (!event) return false;
  if (event->type == EVENT_WEATHER_UPDATE) {
    // Hava durumu görevi yeni veri yayınladı -> ikonu yenile.
    // UI task bağlamındayız; doğrudan render güvenli.
    if (s_activity_icon_cloud)
      weather_icon_render(s_activity_icon_cloud,
                          (weather_condition_t)event->data);
    return true;   // olay tüketildi
  }
  return false;    // ilgilenmiyorum -> diğer dinleyicilere geçsin
}
Hava durumu görevi yeni veri yayınlar. Kadran bu olayı yakalar, ikonu yeniler ve true dönerek olayı tükettiğini bildirir.
Çözünürlük uyumu: ölçü sabitleri
9 / 10
// launcher_app.cpp — ölçü sabitleri (tek blok, uygulamanın başında)
#ifdef BOARD_VARIANT_LCD128          // 240×240 yuvarlak LCD
  #define L_SCR_W    240
  #define L_CELL_W    88               // grid hücresi
  #define L_CELL_H    92
  #define L_ICON      64               // uygulama ikonu
  #define L_SYM_FONT  (&lv_font_montserrat_28)
#else                                 // 410×502 AMOLED (varsayılan)
  #define L_SCR_W    410
  #define L_CELL_W   120
  #define L_CELL_H   128
  #define L_ICON      95
  #define L_SYM_FONT  (&lv_font_montserrat_36)
#endif
// UI kodu her yerde SADECE sabiti kullanır:
lv_obj_set_size(cell, L_CELL_W, L_CELL_H);
Her uygulama, ekrana bağlı ölçülerini varyanta göre seçilen tek bir sabit bloğunda tanımlar. Arayüz kodu yalnızca bu sabitleri kullanır.
Değişmezlik kuralı: varsayılan dal #else tarafında orijinal değerlerin birebir aynısını taşır. Böylece varsayılan derleme tek bayt bile değişmez.
Küçük ekran için pratik notlar
10 / 10
  • İkon ve daire oranını koruyun. 40 piksellik dairede 24 piksellik sembol, 26 piksellik dairede 16 piksele iner.
  • Liste satır aralığını satır yüksekliğinin yaklaşık 8 piksel fazlası olarak ayarlayın. AMOLED değerini olduğu gibi taşımak devasa boşluklar üretir.
  • Yuvarlak ekranda üst ve alt kenarlarda görünür genişlik daralır. Başlık ve saat gibi öğeleri yan yana değil alt alta yerleştirin.
Basit yükseklik ya da konum farkları için satır içi bir #ifdef de yeterlidir.
